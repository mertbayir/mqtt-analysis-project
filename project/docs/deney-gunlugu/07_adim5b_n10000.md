# 07 — Adım 5b: Ölçek büyütme (N = 10.000)

Tarih: 16 Ekim 2026
Durum: **Matris başlıyor** (hipotezler matris sonuçları görülmeden önce yazıldı; olurluk pilotunun sonucu yazım sırasında biliniyordu)
Rapor bölümü: Bulgular (5.6 ölçek etkisi), Sınırlar
Önceki adım: `06_adim5_baglanti_sonrasi_yuk.md` (N = 5.000, 18 koşu)

## Amaç

06'da en iyi denge gibi görünen **rastgeleli A + B1** hücresi N = 5.000'de sunucu CPU'sunu %85'e çıkarmıştı. Soru: cihaz sayısı ikiye katlanınca (10.000) bu hücre hâlâ taban düzeyinde mi kalıyor, yoksa doyma noktası aşılıyor mu? Ve doyduğunda B2 (ayrık boşaltma) işe yarıyor mu?

## Kurulum

06 ile aynı (zaman çizelgesi, iş yükü, sunucu/toplayıcı/simülatör kaynak payları, tek yönlü saat), yalnızca **N = 10.000**. Başlangıç yayılımı 20 sn **korundu** (varış hızı iki katına çıkıyor; N ile yayılım birlikte değişmediği için bu da ölçeğin bir parçasıdır). Simülatör konteynerinin CPU/bellek sınırı değiştirilmedi (4 CPU / 3 GB).

## Olurluk pilotu (nihai veri değil)

`adim5_ustel-rastgele_b1_n10000_s1_pilot10k` (rastgeleli A + B1, tek koşu):

| Ölçüt | N = 5.000 (06, medyan) | N = 10.000 (pilot) |
|---|---|---|
| Taban alarm p99 | ≈ 30 ms | 54 ms |
| Alarm p99 tepe | 51 ms | **6.036 ms** |
| 100 ms üstü süre | 0 sn | **27 sn** |
| Boşaltma bitişi | 28,9 sn | 32,6 sn |
| Eşitleme p99 | 6 ms | 1.270 ms |
| Sunucu CPU tepe | %85 | **%92** |
| Kayıp / tekrar | 0-1 / 0 | 0 / 0 (1.079.072 mesaj) |

Koşu hatasız tamamlandı: 10.000 cihaz bağlandı, tüm mesajlar ulaştı. Yani **N = 10.000 bu düzenekte çalıştırılabiliyor** ve rastgeleli A + B1 hücresi 5.000 ile 10.000 arasında bir yerde doyuyor (tek koşu).

## Hipotezler (matris öncesi yazıldı)

| # | Hipotez | Not |
|---|---|---|
| H11 | **Rastgeleli A + B1, N = 10.000'de** alarm p99 tepesi tabanın en az 10 katıdır (doyma) | Pilotta gözlendi (≈ 110 kat); tekrarlı koşuyla doğrulanacak |
| H12 | **Rastgeleli A'da B2, B1'e göre** (N = 10.000) tepeyi en az %50 düşürür; 06'da (N = 5.000) bu yönde etki yoktu, doyma ile B2 anlamlı hâle gelir | **Çürüyebilir** |
| H13 | **B2 ile** (her iki A için) alarm p99 tepesi N = 10.000'de **500 ms'nin altında** kalır; bedeli boşaltma bitişinin ≥ 60 sn olmasıdır | **Çürüyebilir** |
| H14 | **Üstel A + B1**, N = 10.000'de rastgeleli A + B1'den kötüdür (tepe daha yüksek) | **Çürüyebilir** |
| H15 | Tüm koşularda tekrar = 0; kayıp ≤ 1 mesaj (06'daki bulguya göre) | **Çürüyebilir** |

## Tasarım

| Öğe | Değer |
|---|---|
| Faktörler | A (üstel, rastgeleli üstel) × B (b1, b2) = 4 hücre; B0 yok (06'da zaten taban düzeyinde, ölçeğe bağlı değil varsayımı bir sınırdır) |
| N | 10.000 |
| Tekrar | 3 blok (tohum 1, 2, 3), her blokta rastgele sıra |
| Toplam | 12 koşu, ≈ 50 dk |
| Sürüm etiketi | `v7` |

## Sınırlar (önceden bilinen)

- Pilot ve matris aynı simülatör konteynerinde 10.000 cihaz koşturuyor (4 CPU / 3 GB); simülatörün kendi yükü gecikmeye karışmış olabilir. Taban gecikmenin 30'dan 54 ms'ye çıkması buna işaret edebilir (doğrulanmadı).
- B0 N = 10.000'de koşulmadı.
- Yayılım 20 sn sabit tutuldu; varış hızı da iki kat oldu.
- 06'daki tüm sınırlar geçerli (tek makine, tek çekirdekli Mosquitto, TLS yok, tek kesinti türü).
